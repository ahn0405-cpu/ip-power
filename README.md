# ⚡ IP-Power 플랫폼 — 전력 이슈 뉴스·특허 인텔리전스

반도체 클러스터·AI 데이터센터·**3대 메가프로젝트** 시대에 가장 큰 변수인 **전력 이슈** —
관련 **뉴스는 매일**, **특허는 매주** 자동 수집해 누적 아카이브하는 정적 웹사이트입니다.
사이트는 **🏠 홈(대시보드) / 📰 뉴스 / 📄 특허** 세 탭으로 구성됩니다 — 홈은 브리핑·트렌드·핵심
지표를 한눈에 요약하고, 뉴스·특허 탭에서 세부 항목을 탐색합니다.

- **뉴스는 키 불필요**(Google 뉴스 RSS) · **특허는 EPO OPS 공식 API**(무료 등록키, `OPS_KEY`/`OPS_SECRET`).
- **완전 자동** — GitHub Actions가 수집 → 빌드 → GitHub Pages(`gh-pages`)로 배포합니다.
- **의존성 없음** — 순수 파이썬 표준 라이브러리로만 동작합니다.

> 본 사이트는 이슈 **아카이브용**이며 특정 투자·정책 판단을 권유하지 않습니다.
> 뉴스 제목·요약·링크는 각 언론사 원문, 특허는 Espacenet 원문으로 연결됩니다.

## 화면 (인터랙티브 리더)
`index.html` 한 장짜리 앱이 전체 아카이브를 담아 **브라우저에서 통합검색·다중필터·정렬**합니다.
데이터가 페이지에 인라인되어 백엔드 없이, `file://` 로컬 열람과 GitHub Pages 모두 동작합니다.
- **🏠 홈(대시보드)**: 기본 착지 화면. **🧭 서술형 브리핑(최신+지난 브리핑 타임라인)** + 트렌드
  인사이트 + 핵심 지표 KPI + **출원인×분야 매트릭스 요약**을 한자리에. 요소를 누르면 뉴스/특허 탭의
  상세로 연결. 브리핑은 날짜별로 누적 아카이브됩니다.
- **📰 뉴스 / 📄 특허 탭** 전환 (상세 목록·통계)
- **🔎 트렌드 인사이트**(홈): LLM 없이 순수 계산으로 매일 자동 생성.
  ① 🔥 **요즘 뜨는 키워드**(최근 7일 제목, 이전 대비 ▲, 눌러서 검색) ② 📈 **이슈 흐름**(카테고리별
  최근 vs 이전 증감) ③ 📄 **이번 주 공개 특허**(최신 공개분 제목·출원인, 클릭 시 원문).
  키워드·행을 누르면 곧바로 해당 검색/카테고리 필터로 연결됩니다.
- **통합 검색**: 제목·요약·출처·출원인·공개번호를 전 기간에서 즉시 검색
- **다중 필터**: 카테고리(다중), 출원인 국적(🇺🇸🇰🇷🇨🇳🇯🇵🇪🇺), 정렬(최신/오래된순), "✨ 새 항목"(지난 방문 이후)
- **가벼운 개요**: 누적/수집기간/최근/신규 스탯 타일 + 기간별 추이 스파크라인
- **특허 통계 뷰**(특허 탭 `목록 / 📊 통계` 토글): **🧩 출원인 × 분야 매트릭스**가 핵심 —
  출원인을 국적(🇺🇸🇰🇷🇨🇳🇯🇵🇪🇺)별로 묶어, 각 기업이 8개 전력 분야 중 **어디에 최근 특허를
  냈는지**를 한눈에(칸을 누르면 그 출원인·분야 특허로 드릴다운). 아래에 분야별 주요 출원인 +
  출원인 랭킹. 현재 필터(분야·국적·검색)를 그대로 반영
- **공유 가능**: 필터·뷰 상태가 URL 해시에 반영 → 링크로 특정 필터/통계 화면 공유
- 라이트/다크 자동, 모바일 대응

## 카테고리
뉴스: ⚡전력수급·전력난 · 🔌송·변전·전력망 · ☢️원전·SMR · 🌿재생에너지 · 🖥️데이터센터·AI 전력 ·
🏗️반도체 클러스터·메가프로젝트 · 🏛️전기요금·정책 · 🏭전력설비·산업
특허: ☢️원전·SMR · 🌿재생에너지·저장 · 🧮계량·스마트그리드 · 🖥️데이터센터·무정전전원 ·
⚡전력수급·수요관리 · 🏗️전력반도체·전력변환 · 🏭전력설비·기기 · 🔌송·변전·전력망 —
**CPC 코드로 분류**합니다(H02J·H02M·G21·H02S·H01H·Y04S 등).
수집은 **큐레이션한 주요 출원인 65곳**(미국·한국·중국·일본·유럽) × 전력 CPC 로 하며,
출원인·CPC 는 `patent_config.py` 의 `APPLICANTS` / `CATEGORIES` 에서 편집합니다.

## 구성
| 파일 | 역할 |
|------|------|
| `news_config.py` / `patent_config.py` | 카테고리·검색 키워드·경로 설정 (뉴스 / 특허) |
| `news_source.py` | Google 뉴스 RSS 수집·파싱 (차단/오프라인 시 MOCK 폴백) |
| `patent_source.py` | EPO OPS 공식 API 수집 — 출원인×전력 CPC (키 없음/실패 시 MOCK 폴백) |
| `news_archive.py` / `patent_archive.py` | 날짜별(뉴스)·주별(특허) JSON 누적 + 중복 제거 · 출원인 집계(`stats.json`) 누적 |
| `insights.py` | 뉴스 트렌드 인사이트 계산 (뜨는 키워드·이슈 흐름) — 무LLM·순수 계산 |
| `brief_archive.py` | 서술형 브리핑(brief.json) 날짜별 누적 |
| `site_render.py` | 인터랙티브 SPA 렌더 (홈 대시보드 + 인라인 데이터 + 검색/필터/정렬, 라이트·다크) |
| `build_site.py` | 수집→누적→사이트(index.html) 재생성 오케스트레이션 |
| `selftest.py` | 스모크 테스트 — OPS 응답을 스텁으로 끼워 라이브 수집 경로를 네트워크 없이 실행 |
| `.github/workflows/daily-power-news.yml` | 매일 08:00 KST → 뉴스 수집 + 출원인 집계 11곳 회전 후 배포 |
| `.github/workflows/weekly-power-patents.yml` | 매주 월 08:20 KST → 특허 목록 수집 후 배포 |

## 로컬 미리보기
```bash
python build_site.py                 # 뉴스+특허 둘 다 수집 후 site/ 생성 (의존성 없음)
# site/index.html 을 브라우저로 그냥 열기 (데이터 인라인이라 file:// 에서도 검색·필터 동작)
# (네트워크 차단·오프라인이면 자동으로 샘플(MOCK) 데이터로 빌드됩니다)
```
개별 수집: `python build_site.py --collect news` / `--collect patents` / `--collect none`(재빌드만).

## GitHub Pages 공개 (최초 1회 설정)
1. 코드를 push 하고 **Actions 탭**에서 워크플로를 한 번 수동 실행(`Run workflow`) → `gh-pages` 생성.
2. **Settings → Pages → Source** 를 **Deploy from a branch → `gh-pages` / `(root)`** 로 지정.
3. `https://<계정>.github.io/<저장소이름>/` 에서 열립니다.
   (주소는 저장소 이름을 따라갑니다 — 이름을 바꾸면 canonical·사이트맵도 함께 따라옵니다.)
   이후 뉴스는 매일, 특허는 매주 자동 갱신됩니다.

> 두 워크플로는 실행마다 `gh-pages`에서 **뉴스·특허 아카이브를 모두 복원**한 뒤 자기 담당분만
> 더해 사이트 전체를 다시 만듭니다 → 어느 쪽이 돌아도 다른 탭 데이터는 유지, 히스토리는 항상 1커밋.
> 두 워크플로는 같은 concurrency 그룹이라 `gh-pages` 배포가 서로 겹치지 않습니다.

## 특허 수집 기간 (중요)
- **1회 조회 범위**: 수집 시점 기준 **최근 90일 공개분**(`PATENT_LOOKBACK_DAYS`, 기본 90).
- **누적 방식**: 매주 월요일 조회해 **이미 아카이브에 없는 것만** 추가합니다 → 시간이 지날수록
  아카이브가 담는 공개일 범위는 넓어집니다.
- **주별 파일명(`data/patents/YYYY-MM-DD.json`)은 '수집한 주'**이며 공개일과 다릅니다.
  사이트는 실제 **공개일 범위**를 특허 탭 개요 타일·목록 상단·통계 뷰·홈 KPI 에 표시합니다.
- 출원인당 최대 `PATENT_PER_APPLICANT`(기본 50)건까지 담으므로, 대형 출원인은 해당 기간의
  전수가 아니라 **최신 표본**입니다.
- **랭킹은 표본이 아니라 실제 건수**로 냅니다. OPS 가 알려주는 전체 건수(`total-result-count`)를
  `data/patents/stats.json` 에 따로 누적해, 저장 상한(50)에 랭킹이 왜곡되지 않습니다.
  - 출원인별 **총 건수**: 특허 목록을 받을 때 함께(주 1회).
  - 출원인 × **공개 특허청**(US/KR/CN/JP/EP/WO) 건수: 전 출원인을 한 번에 조회하면 OPS
    무료 쿼터에 걸려 403 이 나므로(실측), **매일 뉴스 실행에 얹어 11곳씩 회전**합니다
    (`PATENT_OFFICE_BATCH`, 65곳 ≈ **6일에 한 바퀴**). 집계는 항상 **병합**이라 부분 실행이
    이전 값을 지우지 않고, 403 을 만나면 그 자리에서 멈추고 다음 날 이어서 채웁니다.

## 특허 소스에 대한 참고
특허는 **EPO OPS(유럽특허청 공식 Open Patent Services)** 로 수집합니다. `developers.epo.org`
에서 앱을 등록해 받은 **무료 키**(Consumer Key/Secret)를 저장소 Secret `OPS_KEY`/`OPS_SECRET`
으로 넣으면 됩니다. 공식 API라 요청 제한이 넉넉하고, 응답에 **CPC 분류**와 **공개 특허청**이
포함돼 분야 분류가 키워드 추정보다 정확합니다. 키가 없거나 OPS 장애 시에는 MOCK 으로
폴백해 **뉴스 탭과 사이트 빌드는 항상 정상 동작**합니다.

> 매트릭스의 그룹축은 **출원인 국적**(미국·한국·중국·일본·유럽)이며, 특허가 실제로 공개된
> **특허청(office)** 과는 다릅니다(한 기업이 US·EP·WO 등 여러 곳에 공개). office 는 각 특허
> 카드에 표시됩니다.


## 시각·키워드 편집
- 수집 시각: 각 워크플로의 `cron`(UTC, KST−9). 예: 08:00 KST → `0 23 * * *`.
- 키워드/카테고리: `news_config.py` / `patent_config.py` 의 `CATEGORIES`.
- 건수·주기 등 세부: `.env`(또는 워크플로 env)의 `NEWS_*` / `PATENT_*`.
